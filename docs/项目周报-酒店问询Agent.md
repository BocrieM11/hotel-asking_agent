# 🏨 酒店问询Agent — 项目周报

> 周期: 2026年6月8日–6月12日 | 汇报人: 问询模块负责人

---

## 一、项目概述

酒店智能Agent共5大模块（控制/点餐/问询/客房服务/TTS语音识别），本人负责**问询子系统**。从零搭建，经历规则引擎→LLM Agent三代架构演进，最终交付可本地部署、零成本、语音友好的生产级Agent。

---

## 二、四天开发实录

### 第一天（6/8）— Express框架 + LLM首次接入

搭建 Express 框架并完成 LLM 首次接入，跑通「用户输入 → LLM → 回复」最小闭环，验证技术可行性。

### 第二天（6/9–6/10）— BRD规则引擎 + 酒店数据 + 混合检索

通读 BRD 全表，从55个意图中锁定问询模块6个核心意图（WEATHER_QUERY / TIME_QUERY / FAQ_QUERY / HOTEL_CALL / EXIT / NEED_CLARIFY），按 General、IntentDefinitions、SlotDefinitions、CapabilityMatrix 四张配置表落地规则引擎，实现 BRD §9.1 八步处理管线。爬取威尼斯人酒店198项全量数据，建立350+中英同义词库和8组消歧规则，通过关键词正则 + 混合检索完成FAQ精准问答。最终交付 v2.4：17个源文件、~7,000行代码、60+条规则、600+测试用例。

### 第三天（6/11）— 天气/时间API + 架构革命

接入 Open-Meteo 天气 API 和系统时区映射补全功能后，发现规则引擎三大瓶颈：未预见问法直接失败、每加话题需改四层代码、350+同义词仍覆盖不足。推倒 7,000 行规则引擎，重构为 LLM Agent + Tools 架构，代码精简至 500 行（-93%），切换本地 Ollama 实现零成本离线部署。

### 第四天（6/11–6/12）— 规则归零 + 语音深度优化

规则全部归零，LLM 百分百自主决策。上线 bge-m3 RAG 语义检索（91段落）、高频缓存、会话持久化和按时段主动推荐。针对语音交互场景进行四轮优化：修复 WMO 天气码表（27°C不再报雪）、建立服务边界（送物/点餐/控制→礼貌拒绝）、动态控制KB注入量（宽泛给方向、具体给详情）、Prompt精简至8行。最终交付 v3.3：600行代码、月成本0元、真实住客准确率90.7%。
